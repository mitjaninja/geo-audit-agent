# Sakura Spark

Match-3 в аниме-стиле для Telegram Mini App. Требования — [PRD.md](PRD.md), этапы — [ROADMAP.md](ROADMAP.md).

## Структура

- `packages/core` — правила match-3 без движка: детерминированный RNG, поле, матчи (включая L/T), каскады, гравитация, досыпка, перемешивание, очки, ходы, реплей.
  Спецфишки и комбо — в `src/specials.ts`, правила описаны в комментариях к `Special` и `ComboKind` в `src/types.ts`.
  Цели и звёзды — `src/goals.ts`, блокеры и порталы — `src/blockers.ts`, формат и валидатор уровня — `src/level.ts`.
- `packages/sim` — боты (случайный и жадный) и автотест уровней против коридоров win rate из PRD.
- `apps/client` — Telegram Mini App на Phaser 3: рисует события ядра, ввод свайпом и тап-тапом, HUD, тема Telegram.
- `apps/server` — API и бот: вход по подписи Telegram, жизни, попытки с проверкой реплея, прогресс (SQLite), раздача клиента.
- `levels/` — уровни в JSON, имя файла = id с нулями (`0001.json`). Тест проверяет каждый файл.

## Формат уровня

```jsonc
{
  "id": 2, "width": 8, "height": 8, "colors": 5, "moves": 25,
  "difficulty": "normal",              // normal | hard | superHard
  "shape": ["_######_", "..."],         // # клетка, _ дыра (необязательно)
  "jelly": ["_000000_", "..."],         // слои желе 0–2 (необязательно)
  "blockers": [".iI.v...", "..."],     // . нет, i/I лёд, f туман, k/K сундук, m/M дайфуку, v лианы
  "portals": [{ "from": [2, 3], "to": [4, 4] }],
  "lanterns": { "total": 2, "maxOnBoard": 2, "spawnChance": 0.3 },
  "goals": [                            // 1–3 цели, нужны все
    { "type": "score", "target": 1500 },
    { "type": "jelly" },
    { "type": "lanterns", "count": 2 },
    { "type": "collect", "color": 1, "count": 20 },
    { "type": "fog" }
  ],
  "stars": [1500, 3000, 5000]           // пороги очков; победа = минимум 1 звезда
}
```

Правила блокеров — в комментарии к `Blocker` в `src/blockers.ts`. Фишки пролетают сквозь
блокеры и дыры; в выход портала сверху ничего не падает — только из входа.

Сид поля в уровень не входит: сервер выдаёт его на каждую попытку (`gameOptionsFromLevel(level, seed)`).

## Команды

```bash
npm install
npm run typecheck
npm test
npm run server:dev                         # сервер на :8787 с dev-входом (без Telegram)
npm run dev                                # клиент на http://localhost:5173/?devUser=1 (API проксируется на :8787)
                                           # ?offline=1&level=3&seed=42 — без сервера, фиксированное поле
npm run build                              # сборка в apps/client/dist
npm run smoke                              # сборка + e2e в Chromium, скриншоты в apps/client/e2e/out
npm run autotest -- --runs 1000 --bot casual  # все уровни против коридоров win rate PRD
npm run tune -- levels/0021.json --write   # подобрать ходы и пороги звёзд под коридор
npm run report                             # воронка, D1, win rate по уровням из базы (DB_PATH)
npm run autotest -- levels/0003.json --bot random --runs 300 --json report.json
```

Автотест печатает win rate с 95% интервалом, целевой коридор PRD и вердикт (`ok` / `TOO HARD` / `TOO EASY`),
распределение звёзд, средний остаток ходов при победе и долю «почти побед» (проигрыш при прогрессе целей ≥ 80% —
кандидаты на окно «+5 ходов»). `--assist 0.04` — проверить, как помогает скрытое облегчение. `--strict` — код
выхода 1 при выходе из коридора (для CI).

Жадный бот примеряет каждый ход на копии партии с чужим сидом, поэтому не видит будущую досыпку.
Он проходит почти всё, поэтому уровни настраиваются **казуальным** ботом: половина ходов жадная, половина
случайная — допущение «так играет живой человек» до данных софт-лонча (`CASUAL_SKILL` в `packages/sim`).
Когда появятся реальные win rate из `npm run report`, коэффициент калибруется под них.

Тюнер (`npm run tune`) бинарным поиском подбирает число ходов, чтобы win rate казуального бота попал
в коридор PRD (у уровней 1–20 — в 97%, а не в центр коридора, иначе первые уровни становятся гонкой),
и ставит пороги звёзд по счетам побед: 2★ — медиана, 3★ — 85-й перцентиль.

## Уровни, карта, обучение

- Эпизод = район Хоширо = 15 уровней: 1–15 Храмовый холм, 16–30 Торговая улица.
- Новые механики вводятся по одной, перед уровнем с новинкой — короткие реплики персонажей
  (`intro` в JSON уровня, показываются один раз). Уровень 1 — обучающий ход (`tutorial`): рука показывает
  свап, другие ходы до него не принимаются.
- После 7 секунд бездействия Пон подсказывает лучший ход.
- Сложные уровни (`difficulty: "hard"`) — 25 и 30 (финал района, туман Курогири).

## Аналитика

События PRD пишет сервер — по реплею, им можно доверять: `install`, `level_start`, `level_win`
(очки, звёзды, остаток ходов), `level_fail` (причина, остаток ходов, прогресс цели), `lives_empty`.
С клиента принимаются только `session_start`, `session_end`, `hint_shown`, `tutorial_complete`.
`booster_used`, `moves_purchased`, `offer_*` появятся вместе с бустерами и платежами (этапы 11–12).

## Пример

```ts
import { Match3Game } from '@sakura/core';

const game = new Match3Game({ width: 9, height: 9, colors: 5, moves: 25, seed: 42 });
const { valid, events } = game.swap({ a: { row: 4, col: 4 }, b: { row: 4, col: 5 } });
// events: swap → cascade × N → (shuffle) — клиент проигрывает их как анимации

// на сервере: тот же сид + история ходов = тот же счёт
Match3Game.replay(game.options, game.history).score === game.score;
```

## Клиент

Сцена не знает правил: она отправляет ход в ядро и проигрывает полученные события (свап, каскады,
перемешивание, рост тумана, финал). После каждого хода картинка дополнительно сверяется с состоянием
ядра — если анимация где-то разошлась с правилами, поле всё равно придёт к верному виду.

Графика временная — рисуется кодом в `src/textures.ts`. Когда появится арт, достаточно загрузить
картинки под теми же ключами текстур. Canvas рисуется в device pixels (до 2×), чтобы на телефонах
не было мыла. Таймер уровней на время идёт по настенным часам и встаёт на паузу, когда Mini App свёрнут.

## Сервер

Клиенту сервер не доверяет: клиент присылает только список ходов, а счёт, звёзды и победу сервер получает,
проигрывая партию тем же ядром с тем же сидом. Сид выдаёт сервер при старте попытки.

- **Вход** — заголовок `Authorization: tma <initData>`, подпись Telegram проверяется на каждом запросе
  (данные старше суток не принимаются). `Authorization: dev <id>` — только при `DEV_AUTH=1`.
- **Жизни** — 5, +1 за 30 минут по серверному времени. Жизнь резервируется при старте попытки и возвращается
  при победе; брошенная партия (закрыли приложение) засчитывается поражением при следующем старте.
- **Скрытое облегчение** — после 5+ поражений подряд на уровне сервер выдаёт попытку с `assist`;
  игрок его не видит, реплей проверяется с тем же значением.
- **Уровень на время** — победа, присланная позже лимита (+15 с на сеть), не засчитывается.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/me` | профиль, жизни, открытый уровень, звёзды по уровням, серверное время |
| GET | `/api/levels` | список уровней |
| POST | `/api/attempts` `{levelId}` | начать попытку: уровень, сид, жизни; 403 — уровень закрыт, 409 — нет жизней |
| POST | `/api/attempts/:id/finish` `{swaps, timedOut}` | закончить: сервер проигрывает ходы; 400 — ходы не сходятся |
| POST | `/telegram/webhook` | апдейты бота (секрет в `X-Telegram-Bot-Api-Secret-Token`) |

Хранилище — встроенный в Node 22 SQLite (`node:sqlite`) за асинхронным интерфейсом `Store`,
чтобы позже заменить на Postgres без переделки логики.

### Запуск в Telegram с телефона (Render)

Всё делается в браузере, по чертежу `render.yaml` в корне репозитория:

1. Зайти на render.com через GitHub.
2. **New → Blueprint**, выбрать репозиторий `geo-audit-agent` и ветку `sakura-spark`.
3. В поле `BOT_TOKEN` вставить токен бота. `WEBHOOK_SECRET` Render сгенерирует сам.
4. **Apply**. Сборка идёт несколько минут, потом можно писать боту `/start`.

Нужен платный инстанс Starter: на бесплатном нет диска под базу, и он засыпает.

### Запуск в Telegram (Fly.io)

Сервер раздаёт клиент и API с одного адреса. При старте он сам обновляет профиль бота и ставит вебхук
и кнопку меню «Играть» на `https://<app>.fly.dev`. SQLite живёт на томе `/data`, поэтому машина одна.

```bash
cd sakura-spark
fly auth login
fly apps create sakura-spark                 # имя занято — возьмите другое и поменяйте app в fly.toml
fly volumes create sakura_data --region ams --size 1
fly secrets set BOT_TOKEN=<токен от @BotFather> WEBHOOK_SECRET=$(openssl rand -hex 16)
fly deploy
```

Потом написать боту `/start`, и кнопка «Играть» откроет игру. Логи: `fly logs`, там будет строка
`bot: webhook https://…/telegram/webhook`.

Без Fly подойдёт любой хостинг, где есть Docker или Node 22.13+ и HTTPS: нужны переменные `BOT_TOKEN`,
`WEBHOOK_SECRET`, `PUBLIC_URL` (https-адрес) и `DB_PATH` на постоянном диске. Профиль бота без деплоя
обновляет `BOT_TOKEN=… npm run setup-bot`.

Переменные описаны в `apps/server/.env.example`.

## Игра в чатах

Любой игрок зовёт чат в челлендж: `@<бот>` в поле ввода (inline-режим) или кнопка «💬 В чат» на карте
(`shareMessage`). В чат уходит карточка с уровнем и кнопками «Играть» и «🏆 Рейтинг».

- **Челлендж чата.** Все играют один уровень с одинаковым сидом 24 часа, рейтинг — лучший счёт.
  Первая попытка бесплатна, каждая следующая стоит жизнь. Облегчения в комнате нет, прогресс карты
  не меняется. Ход быстрее 250 мс сервер считает скриптом и не засчитывает результат.
- **Помощь жизнью.** Карточка «… просит жизнь» с кнопкой «Подарить жизнь»: каждый в чате дарит один раз,
  до 5 подарков; себе подарить нельзя.
- **Лимит** — 5 карточек в день на игрока (считаются только ушедшие в чат).
- **Новичок из чата** получает подсказку хода сразу на первых трёх ходах.

Бот правит карточку: топ-5 и число сыгравших. Для этого нужен `inline_message_id` карточки — он приходит
с первым нажатием любой кнопки в ней, а с включённым inline feedback — сразу после отправки.

Две необязательные настройки в @BotFather делают чат-режимы удобнее:

1. **Main Mini App** (Bot Settings → Configure Mini App → включить, URL — адрес игры): кнопка «Играть»
   в карточке открывает игру сразу (`startapp`). Без неё ссылка ведёт в личку с ботом, и он даёт кнопку
   игры с той же комнатой. Сервер определяет режим сам по `getMe` при старте.
2. **Inline feedback** (`/setinlinefeedback` → 100%): карточка начинает обновляться сразу, а не после
   первого нажатия кнопки.

## Экономика и Stars

Валюта — кристаллы 💎, покупаются только за Telegram Stars (`XTR`). Цены живут в `apps/server/src/economy.ts`.

- **Бустеры перед уровнем** — «Луч и бомба», «Радужный кристалл», «+3 хода». Ставятся сидом попытки,
  поэтому реплей на сервере совпадает с партией клиента. На старте игрок получает по 3 штуки каждого.
- **Бустеры в уровне** — молоток, свободный свап, перемешивание. Каждое применение — ход в истории,
  сервер списывает бустер только после проверки реплея.
- **+5 ходов** — когда ходы кончились: 9 → 15 → 25 💎 за попытку.
- **Полные жизни** — 12 💎. **Стартовый пак** — 50 ⭐ один раз, 48 ч после 15-го уровня.
  **Копилка** — +3 💎 за победу, до 120; разбить — 150 ⭐, если накопилось хотя бы 30.
- **Оплата.** Сервер создаёт счёт (`createInvoiceLink`), клиент открывает `openInvoice`. Кристаллы
  начисляются только по `successful_payment` и ровно один раз на платёж. `/paysupport` и `/terms` — в боте.
- **Возврат.** `/refund <charge_id>` в личке с ботом — только для id из `ADMIN_IDS` (переменная окружения
  на хостинге, через запятую). Сервер вызывает `refundStarPayment` и списывает начисленное.

Настоящую оплату Stars проверить можно только с телефона реального пользователя: тесты сервера
подменяют Bot API.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/shop` | цены, паки, стартовый пак, копилка |
| POST | `/api/shop/buy` `{item, count}` | купить бустер за кристаллы |
| POST | `/api/lives/refill` | полные жизни за кристаллы |
| POST | `/api/purchases` `{product}` | ссылка на счёт Stars |
| POST | `/api/attempts/:id/extend` `{moves}` | +5 ходов в текущей попытке |

## Remote config и A/B

Цены, офферы и сложность меняются без релиза клиента — командами боту в личке. Они работают только для
id из `ADMIN_IDS` (переменная окружения на Render, id через запятую; свой id бот скажет по `/myid`).

| Команда | Что делает |
|---|---|
| `/config` | действующий конфиг и последние версии |
| `/config_set <JSON>` | заменить конфиг целиком; действует сразу. Ошибка — ответ с путём к полю, ничего не меняется |
| `/config_rollback` | вернуть предыдущую версию (история сохраняется) |
| `/report` | сводка: воронка, D1, уровни, эксперименты по вариантам |

```json
{
  "economy": { "refillLives": 10, "extendPrices": [9, 12, 20], "packs": { "pack10": { "stars": 45 } } },
  "levels": { "17": { "moves": 2 }, "12": { "time": 10 } },
  "assistAfterLosses": 4,
  "experiments": [
    { "id": "starter_price", "active": true, "variants": [
      { "name": "base", "weight": 1 },
      { "name": "cheap", "weight": 1, "config": { "economy": { "starter": { "stars": 35 } } } }
    ] }
  ]
}
```

- `economy` — любые поля из `apps/server/src/economy.ts`, частично; остальное берётся по умолчанию.
- `levels` — сдвиг ходов (±20, не меньше 5) и секунд уровня (±60, не меньше 20). Попытка запоминает свои
  ходы и время, поэтому смена конфига посреди партии её не ломает. Челленджи в чатах всегда идут по файлу уровня.
- `assistAfterLosses` — после скольких поражений подряд включается скрытое облегчение (по умолчанию 5).
- `experiments` — игрок попадает в вариант по хешу `id эксперимента:id игрока` с весами: стабильно,
  без хранения. Слои: умолчания → конфиг → варианты активных экспериментов по порядку. Вариант пишется
  в события `level_start`, `offer_shown`, `offer_purchased`; `/report` сравнивает варианты по win rate,
  среднему уровню, платящим, Stars, ARPU и D1.

**Калибровка бота.** В отчёте есть «чистые» партии: без бустеров, облегчения, докупки ходов и сдвига
конфига. Их win rate сравним с казуальным ботом:

```bash
npm run report -- --json > report.json        # apps/server; на хостинге — GET /api/admin/report
npm run calibrate -- report.json              # packages/sim: подбор CASUAL_SKILL и секунд на ход
```

Подобранные значения переносятся в `packages/sim` — и `npm run tune` настраивает уровни под реальных игроков.
