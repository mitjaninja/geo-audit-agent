# Sakura Spark — план этапов

Источник требований — `PRD.md`. Этапы разбивают релизные фазы PRD на куски по 1–2 недели.
Правило: каждый этап заканчивается зелёными `npm run typecheck && npm test` и коммитом;
следующий не начинаем на красных тестах.

## Архитектурное решение

Логика игры живёт в `packages/core` — чистый TypeScript без движка, DOM и сети:

- один и тот же код крутится в клиенте, на сервере (валидация реплеев в чат-режимах) и в боте-тестере уровней;
- детерминизм: сид + список ходов → всегда тот же результат;
- выбор движка (Phaser или Cocos, открытый вопрос PRD) не блокирует работу: клиент только рисует события ядра.

```
sakura-spark/
  packages/core     — правила match-3, детерминированный RNG, формат уровня
  packages/sim      — бот и автотест win rate                 (этап 4)
  apps/client       — Telegram Mini App, рендер               (этап 5)
  apps/server       — API, initData, сохранения, жизни, бот   (этап 6+)
  levels/           — уровни в JSON                            (этап 3+)
```

## Фаза 4. Масштабирование

События (Гонка фонарей, Серия побед, сезонные фестивали), Фестивальный пропуск по подписке Stars,
коллекция карточек, локализация EN / ES / PT.

## Вне кода (параллельно)

Финальное название и проверка товарного знака, художник под аниме-арт, актуальные условия вывода Stars.
